# AGENTS.md — Диалоги PROJECT_MITA

Правила для всего, что лежит в `dialogues/`. Общепроектные соглашения — в корневом `AGENTS.md`.

---

## 0. Коротко

- Формат — **Dialogue Manager 3.10.0** (`addons/dialogue_manager`), файлы `*.dialogue` импортируются в `DialogueResource`.
- Отступы — **только табы**. Пробелы вложенность не создают (компилятор ищет `^\t+`).
- Функциональные теги — только `[#...]` **внутри** реплики. Строка, начинающаяся с `#`, — комментарий и на игру не влияет.
- Эмоции и сторона портрета — наши расширения: `[#happy]`, `[#side=right]` (см. §4).
- Каждую ветку завершаем `=> END`.

---

## 1. Что где лежит и как работает

```
dialogues/
  stage_2.dialogue … stage_6_3.dialogue   — крупные сюжетные сцены по этапам
  1_mom_home/                             — сцены первой главы
  2_mike_room/                            — сцены второй главы
  2_mike_room/furniture/                  — диалоги мебели (bed, fridge, …)
```

- Исходник `.dialogue` — обычный текст. Рядом лежит `.dialogue.import` (настройки импорта) — **не редактировать вручную**, но коммитить вместе с файлом.
- В `.tscn` диалоги подключены как `Resource` по `uid://…` и `res://dialogues/…`. Переименование/перенос файла без обновления сцен ломает ссылки.
- В этом проекте список POT-исходников ведётся вручную: новый файл добавьте в `[internationalization] → locale/translations_pot_files` в `project.godot`, иначе его строки не попадут в POT/переводы.

Точки входа (`~ тайтл`) вызываются из:

| Способ | Что получает игрок |
|---|---|
| `DialogueManager.show_dialogue_balloon(resource, "start", [self])` — `scenes/ui/balloon.tscn` (`dialogue_manager/runtime/balloon_path`) | Портреты, теги эмоций, кастомные функции балуна, HUD-ответы |
| `game_interface_overlay.start_dialogue(resource, title, [self])` — `scripts/ui/game_interface_overlay.gd` | Только текст реплик и кнопки ответов (HUD). **Без портретов и функций балуна** |
| `DialogueEventAction` (`scripts/resources/dialogue_event_action.gd`) | Обёртка над `show_dialogue_balloon`; тайтл задаётся полем `dialogue_start` в сцене |

Следствие: диалоги, которые открываются через HUD (`offices_coffee.dialogue`, `teddy_bear.dialogue`), обязаны обходиться ядром синтаксиса + вызовами автолоадов/методов зоны. См. §4.7.

## 2. Жёсткие правила разметки

1. **Табы, не пробелы.** Один уровень вложенности — один таб.
2. **Тайтл** — `~ имя` в начале строки, без пробелов и точек. Допустимы латиница, цифры, `_` и кириллица.
3. **Ответ** — строка, начинающаяся с `- ` (дефис + пробел).
4. Вложенность задаётся отступом: реплики под `if`/ответом должны быть глубже на один таб.
5. `=> END` (или `=> END!`) — обязательное завершение ветки.
6. Служебное слово в начале реплики экранируется обратным слешем: `\do …`, `\if …`.

## 3. Синтаксис Dialogue Manager 3.10

Полная документация плагина: <https://github.com/nathanhoad/godot_dialogue_manager/tree/main/docs>
(`Basic_Dialogue.md`, `Conditions_Mutations.md`, `State.md`, `Translations.md`).

### 3.1 Реплики

```
Майк: Привет.
Это нарратив — реплика без персонажа.
```

Персонаж — всё до первого `:` в строке. Пробелы вокруг двоеточия — часть соглашения проекта (`Имя: текст`).

### 3.2 Ответы (responses)

```
Майк: Постучать?
- Да
	Тишина.
	=> END
- Нет
	=> END
```

Вложенность ответов не ограничена. Условие на ответ:

```
- Взять флешку [if Inventory.has_item("flash_drive") /]
- Уйти => END
```

Переход на ответе пишется **последним**:

```
- Положить в холодильник => quest_end
```

### 3.3 Тайтлы и переходы

```
~ start
Майк: Текст.
=> END

~ quest_end
do Inventory.remove_item("cola")
=> END
```

- `=> cue` — переход.
- `=>< cue` — переход с возвратом (после `END` во вложенном тайтле поток вернётся назад).
- `=> END` — конец текущего потока (с учётом стека `=><`).
- `=> END!` — конец диалога целиком, независимо от стека возвратов.

```
~ start
Майк: Сейчас будет вставка.
=>< snippets/banter
Майк: …и продолжаем.
=> END!
```

Тайтл, которого нет в файле, — ошибка компиляции. Дубликат тайтла — тоже.

### 3.4 Условия и циклы

```
if GameManager.get_flag("shower_used"):
	Майк: Уже помылся.
elif Quests.is_active("find_cola"):
	Майк: Сначала кола.
else:
	Майк: Ладно.
```

```
while Inventory.get_item_count("cola") > 0
	do Inventory.remove_item("cola")
	Майк: Ещё одна.
```

```
match Quests.get_quest_state("find_cola")
	when 0
		Майк: Не начато.
	when 1
		Майк: В процессе.
	else
		Майк: Готово.
```

Условия комбинируются через `and`/`or` и скобки. `?.` — null-safe доступ (`some_node?.name`).

### 3.5 Мутации (изменение состояния)

```
do Inventory.give_item("coffee_cup")
do GameManager.set_flag("offices_coffee_picked_up")
set some_local = 1
```

| Форма | Поведение |
|---|---|
| `do что-то()` / `$> что-то()` | Вызов с ожиданием (`await`), если функция асинхронная |
| `do! что-то()` / `$>> что-то()` | Вызов без ожидания |
| `set x = …` | Присваивание без ожидания |

**Соглашение проекта: используем `do` и `set`.** `$>`/`$>>` — современный синоним, но в файлах проекта он не применяется; не смешивайте стили в одном файле.

Инлайн-мутации выполняются по мере печати текста:

```
Майк: Я не уверен, что мы знакомы [do wave()], я Майк.
```

`wait(сек)` и `debug(...)` — встроенные мутации. Переменные, объявленные через `set`, живут в `locals`.

### 3.6 Случайные варианты

```
% Майк: Вариант раз.
%2 Майк: Вариант два (вдвое вероятнее).
% [if Quests.is_active("find_cola")] Майк: Только при активном квесте.
```

Инлайн-рандом в тексте:

```
Майк: [[Да|Нет|Может быть]]
```

Пустая строка разделяет независимые группы `%`-строк.

### 3.7 Теги

Теги пишутся в квадратных скобках внутри строки и убираются из отображаемого текста:

```
Эмили: [#shame] Ой…
Майк: [#happy, #side=right] Готов!
Майк: [#mood=happy] Доброе утро.
```

- `line.tags` → `["happy", "side=right"]`.
- `line.get_tag_value("side")` → `"right"`.
- Проектные теги — §4.

### 3.8 Инлайн-BBCode плагина

| Запись | Смысл |
|---|---|
| `[wait=0.5]` | Пауза в печати, секунды |
| `[wait="ui_accept"]` | Ждать нажатия действия |
| `[speed=0.5]` | Множитель скорости печати |
| `[next=1.5]` | Автопереход через N секунд |
| `[next=auto]` | Автопереход по длине текста |
| `[if условие]…[else]…[/if]` | Условие внутри строки |
| `[ID:MY_KEY]` | Статический ID для переводов/озвучки |
| `[img]res://…png[/img]` | Картинка в тексте |

Обычный BBCode Godot (`[b]`, `[color=…]`, `[wave]` и пр.) тоже работает, т.к. текст идёт в `RichTextLabel`.

### 3.9 Подстановки

```
Майк: У меня {{Inventory.get_item_count("cola")}} бутылки.
```

### 3.10 Комментарии

```
# Обычный комментарий, в игру не попадает.
## Заметка для переводчиков — попадёт в POT как TRANSLATORS.
```

`#` может стоять и внутри блока с отступом; на вложенность не влияет.

### 3.11 Импорт и сокращения состояния

```
using GameManager
import "res://dialogues/snippets.dialogue" as snippets
```

`import` позволяет прыгать в чужой файл: `=>< snippets/banter`.
`using` сокращает `GameManager.get_flag(...)` до `get_flag(...)`.
В проекте пока не используется — предпочитайте полные имена автолоадов.

## 4. Наши расширения

Всё ниже — не «стандарт плагина», а код проекта (`scripts/ui/balloon.gd`, `scripts/ui/character_portrait.gd`, `scripts/autoloads/dialogue_globals.gd`, `scripts/enums.gd`).

### 4.1 Портреты: эмоции, сторона, голос

| Тег | Что делает |
|---|---|
| `[#happy]`, `[#sad]`, `[#angry]`, `[#shame]` | Эмоция портрета говорящего. Список — `Enums.Emote` |
| `[#side=left]` / `[#side=right]` | Принудительная сторона портрета |
| `[#voice=res://audio/…]` | Озвучка реплики: играет целиком и сама листается дальше |

Правила работы:

1. **Один эмо-тег на реплику.** Если их несколько, побеждает первый в порядке `Enums.Emote` (`HAPPY → SAD → ANGRY → SHAME → DEFAULT`), а не порядок в тексте.
2. **Эмоция не «залипает».** Тег действует только на свою реплику — ставьте его в каждой строке персонажа. (В `balloon.gd` есть код `_character_emotion`/`_update_portraits`, обещающий запоминание, но он **не вызывается** — это мёртвый код.)
3. `[#default]` сейчас ищет файл `<prefix>_default.png`, которого в проекте нет. Чтобы сбросить эмоцию — просто не пишите тег.
4. **Нарративные строки портреты не скрывают.** Нужно убрать персонажа — `do hide_portrait("Майк")`.
5. Сторона: если персонаж уже показан, `[#side=…]` игнорируется и в консоль уходит `push_warning`. Если сторона не указана — свободная слева, затем справа; если заняты обе — warning и левая.
6. Говорящий **обязан** быть в таблице `DialogueGlobals.PORTRAIT_PREFIXES`, иначе `CharacterPortrait.set_character()` упадёт на доступе к несуществующему ключу словаря.

Текущая таблица (`scripts/autoloads/dialogue_globals.gd`):

| Имя в диалоге | Префикс | Файлы в `images/characters/` |
|---|---|---|
| `Майк` | `mike` | `mike.png`, `mike_happy.png` |
| `Мита` | `mita` | `mita.png` |
| `Мама` | `mita` | `mita.png` (временный плейсхолдер, помечен TODO) |
| `Эмили` | `emily` | `emily.png`, `emily_shame.png` |

Формула файла: `<префикс>.png` для базовой эмоции и `<префикс>_<эмоция>.png` для тега.
Если файла нет, `ResourceLoader.load` вернёт `null` — портрет станет пустым, ошибки в консоль не будет.

> Добавили персонажа? Нужны: запись в `PORTRAIT_PREFIXES`, картинки `images/characters/<prefix>.png` (+ варианты эмоций) и, если имя должно переводиться, ключ в `lang/chars.csv`.

### 4.2 Функции балуна (`scripts/ui/balloon.gd`)

Доступны через `do`, потому что первый элемент `temporary_game_states` — сам балун.

| Вызов | Назначение |
|---|---|
| `do fade_out()` / `do fade_out(0.5)` | Затемнение; с аргументом диалог ждёт завершения |
| `do fade_in()` | Плавное появление |
| `do hide_portrait("Имя")` | Убрать портрет персонажа |
| `do play_sound("id")` | Звук из `res://audio/sounds/<id>.{wav,ogg,mp3}`; ждёт окончания |
| `do play_sound("id", false)` | То же без ожидания |
| `do switch_balloon("simple")` | Простой режим: без портретов, имени и панели, чёрный центрированный текст |
| `do wait(0.3)` | Пауза (обёртка над `Timer`) |

Существующие `id` звуков: `rustle`, `open`, `item_pickup`, `shower_wash`, `toilet_flush`. Неизвестный `id` → warning «Звук '…' не найден» и продолжение диалога.

### 4.3 Методы сцены

Сцена/зона может передать себя в `extra_game_states` (`[self]` вторым/третьим аргументом) — тогда её методы вызываются из диалога по имени.

`scripts/1_mom_home/sleep_flashback.gd`:

```
do mom_move(100)
do darken_screen()
do darken_screen_backwards()
do lighten_screen()
do lighten_screen_backwards()
do dialogue_end()
```

`scripts/2_mike_room/mike_room_main_script.gd`:

```
do mike_visible_true()
do mike_visible_false()
do start_screen_fader()
do on_screen_fader()
do off_screen_fader()
do _wait_time(1.0)
do sleep_animation()
do wake_up_animation()
do phone_hand_animation()
do shock()
do irritated()
```

Также `do take_teddy_bear()` из `scripts/experimental/teddy_bear_zone.gd`.

Правило: метод должен существовать на узле, который реально передан в `extra_game_states`. Опечатка в имени = ошибка выполнения, а не компиляции.

### 4.4 Состояние игры (автолоады)

Всегда доступны по имени: `GameManager`, `Quests`, `Inventory`, `SaveSystem`, `DialogueGlobals`, `SoundManager`.

`GameManager` (`scripts/autoloads/game_manager.gd`):

```
if GameManager.get_flag("bed_interacted"):
	…
do GameManager.set_flag("shower_used")
```

- Флаг **обязан** быть объявлен в `DEFAULT_GAME_FLAGS`, иначе `get_flag`/`set_flag` пишут `push_error` и возвращают `false`.
- Сейчас объявлены: `bed_interacted`, `shower_used`, `offices_coffee_picked_up`, `programming_office_samples_puzzle_completed`.
- Прямое обращение `GameManager.game_flags["id"]` допустимо только для существующего ключа.

`Quests` (`scripts/autoloads/quests.gd`):

```
if Quests.is_completed("find_cola"):
Quests.is_started("find_cola") / is_active(…) / is_completed(…)
do Quests.start_quest("find_cola")
do Quests.complete_quest("find_cola")
Quests.get_quest_flag(quest_id, flag_id) / set_quest_flag(…)
```

`Inventory` (`scripts/autoloads/inventory.gd`):

```
if Inventory.has_item("cola"):
do Inventory.give_item("coffee_cup")
do Inventory.remove_item("cola")
Inventory.get_item_count("cola")
```

### 4.5 Озвучка

```
Майк: [#voice=res://audio/sounds/line_001.mp3] Привет.
```

Реплика проигрывается до конца и листается автоматически; индикатор «дальше» скрыт. Файл грузится напрямую через `load`, так что путь должен быть точным.

### 4.6 Переводы

- Текст реплик и ответов автоматически идёт через `tr()`, файл попадает в POT из `project.godot`.
- Имена персонажей переводятся отдельно: `character_label.text = tr(character, "dialogue")`, ключи — в `lang/chars.csv` (`Майк`, `Мита`).
- Поэтому `Имя:` в диалоге должно совпадать с ключом перевода **и** с ключом `PORTRAIT_PREFIXES` символ в символ.
- `[ID:KEY]` — если нужен стабильный ключ (озвучка, правки текста).
- `##` перед репликой — заметка для переводчика.

### 4.7 Ограничения HUD-режима

`game_interface_overlay.start_dialogue()` не создаёт балун: нет портретов, нет `fade_*`, `play_sound`, `wait`, `switch_balloon`, нет тегов эмоций и `side`.

В диалогах, которые открываются через HUD (`offices_coffee.dialogue`, `teddy_bear.dialogue`), используйте только:

- реплики, ответы, условия, `do`-вызовы автолоадов и методов зоны-источника.

Если нужны портреты/катсценные эффекты — запускайте через `DialogueManager.show_dialogue_balloon()` или `DialogueEventAction`.

## 5. Соглашения проекта

- **Имена файлов:** `snake_case`, по локации/этапу: `stage_6_3.dialogue`, `mike_room_morning.dialogue`, `mike_room_sink_day_1.dialogue`. Подпапки — по главам (`1_mom_home/`, `2_mike_room/furniture/`).
- **Тайтл `start`** — для диалогов, которые запускаются «как есть» (HUD, автостарт, мебель). Для интерактивных объектов с несколькими входами — отдельные тайтлы (`inspect_door1`, `cutscene1`, `quest_end`), привязанные в сцене через `dialogue_start`.
- **Тайтлы:** латиница + `_` предпочтительна. Существующие кириллические тайтлы (`~ уборщик`, `~ Пол`) не переименовываем без обновления ссылок в `.tscn`. Опечатки вроде `~ dialoue4` уже привязаны в сценах — переименование тайтла требует синхронной правки `dialogue_start`.
- **Заметки об эмоциях.** Строки `#стандарт`, `#радость`, `#злость`, `#смятение`, `#удивление`, `#мысли`, `#неловко`, `#грустно`, `#испуг`, `#возмущенно`, `#вежливо-угодливо` и подобные — это **комментарии-пометки автора**, а не теги. Они не попадают в `DialogueLine.tags` и ничего не меняют. Если нужна реальная эмоция — добавьте `[#happy]` (и файл портрета).
- **`#`-комментарий** ставим строкой выше того, к чему он относится; внутри блока — с тем же отступом, что и реплики.
- **Завершение:** каждая ветка (в т.ч. каждый ответ) заканчивается `=> END`.
- **Пустые строки:** между тайтлами — 1–2; внутри сцены — для разделения смысловых блоков. Пустая строка также разделяет группы `%`-рандома.
- **Отладочные блоки** в начале файла:

```
~ start
if GameManager.DEBUG_SKIP_INTRO
	do dialogue_end()
	=> END
```

`DEBUG_SKIP_INTRO` сейчас `true` — не копируйте этот блок в новый файл без необходимости, и не забудьте вернуть `false` перед релизом.
- **Стиль вызовов** единый: `do`/`set`, полные имена автолоадов, двойные кавычки, без `$>`.

## 7. Известные ловушки

1. **`has_tag()` в 3.10.0 неполон — но это не наша правка, а поведение апстрима.** В `addons/dialogue_manager/dialogue_line.gd` (ровно как в теге `v3.10.0` репозитория плагина) проверяется только форма `tag=value`, без `tags.has(tag_name)`. В вышедших позже `v3.10.4`/`v3.10.5` и в ветке `v3.x` это уже исправлено добавлением `if tags.has(tag_name): return true`. Пока проект сидит на 3.10.0:
   - `[#voice=res://…]` работает (`has_tag("voice")` → true);
   - `line.has_tag("happy")` для `[#happy]` вернёт **false**.
   В своём коде проверяйте простые теги через `"happy" in line.tags` — так код останется рабочим и после обновления плагина до ≥3.10.4; `has_tag()`/`get_tag_value()` оставляйте для `key=value`-тегов.
2. **`[#emotion=happy]` не работает** — активный путь балуна читает только теги-имена из `Enums.Emote`.
3. **`[#default]`** ищет `<prefix>_default.png`, которого нет. Сброс эмоции — отсутствие тега.
4. **Эмоция не запоминается между репликами** (см. §4.1, мёртвый `_update_portraits`).
5. **`#стандарт` и подобные строки — комментарии**, а не теги. Это самая частая причина «почему портрет не меняется».
6. **Пробелы вместо табов** — самая частая причина «диалог скомпилировался, но ветки не работают».
7. **Ответ без `- `** (например `— Да` с длинным тире) — это обычная реплика, а не выбор.
8. **`GameManager.game_flags["4_shower_use"]`** в `stage_4.dialogue` обращается к ключу, которого нет в `DEFAULT_GAME_FLAGS` → ошибка выполнения. Правильно: объявить флаг и использовать `get_flag("…")`.
9. **Неизвестный говорящий** (например `Билл:`, `Уборщик:`, `Мр.Джекобсон:` — их нет в `PORTRAIT_PREFIXES`) при запуске через балун даёт ошибку доступа к словарю. Добавьте запись и картинку либо ведите такие сцены через HUD.
10. **Переименование `.dialogue`** без правки `uid://`/путей в `.tscn` ломает сцены.
11. **`while`** без изменения условия — бесконечный цикл внутри диалога.
12. **`do` без скобок** (`do some_flag = true`) — это мутация-присваивание, а не вызов метода; для методов нужны скобки.
